# Feature Instructions

Describe a coherent unit of user or business capability that delivers identifiable value.

A Feature should primarily explain:

- who benefits;
- which problem or need is addressed;
- which outcome or behaviour is required;
- why the outcome is valuable;
- what is inside and outside its scope;
- how successful delivery can be verified.

Prefer functional, outcome-oriented language.

Do not define a Feature primarily as:

- an API, service, database, queue, framework or component;
- a technical implementation task;
- a list of screens or fields;
- a broad container for unrelated behaviour.

When technical input is provided, determine the business or user outcome it enables. If the work primarily delivers technical enablement without direct user or business functionality, consider an Enabler instead.

Keep the Feature lean. Include only the smallest coherent scope that produces meaningful value. Move optional enhancements and speculative future needs to follow-up candidates.
