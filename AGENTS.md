# Repository instructions

- Monorepo layout: `apps/web` (React SPA), `services/backlog-api` and `services/agent-service` (Python FastAPI), `libs/py-skills` and `libs/py-contracts` (shared Python packages), `skills/` (Agent Skills), `contracts/` (JSON Schemas, fixtures, OpenAPI snapshot), `apphost/` (Aspire TypeScript AppHost), `deploy/` (Caddy, Keycloak, Kubernetes, fake gateway, Postgres init), `e2e/` (Playwright). Use the pnpm workspace for TypeScript and the uv workspace (`uv sync --all-packages`, `uv run --package <name> …`) for Python.
- Use `pnpm` for all package installation and package scripts. Do not use `npm` or `yarn`.
- Never bundle environment variables into the build. The SPA reads `/config.json` at runtime, and it contains **only** `{ auth: { mode: "platform" | "oidc", authority, clientId, scope }, api: { backlog, agent }, agentId }`. Caddy serves it from container environment variables (`AUTH_MODE`, `OIDC_AUTHORITY`, `OIDC_CLIENT_ID`, `OIDC_SCOPE`, `AGENT_ID`) and proxies `/api/backlog` and `/api/agent`; the Vite dev server serves it from `apps/web/.env.local` and proxies the APIs. The browser never calls an LLM and holds no LLM settings. Tokens live in `sessionStorage` only, never `localStorage`.
- The backend owns all data (PostgreSQL via `backlog-api`; private threads in `agent-service`). The SPA is online-only and keeps **no** data in IndexedDB; `localStorage` is for theme, layout and the selected project only.
- Default guidance (agent principles, per-type instructions, backlog templates) lives in `skills/` as Agent Skills and is the single default source; there is no `apps/web/src/defaults`. Templates are placeholder-free Markdown (no `{{…}}`); each item is one Markdown document. Project owners override guidance per project in the backend (export/import format v5). Bump a skill's `metadata.version` when its content changes.
- Contracts are single-sourced in `contracts/` (JSON Schema + shared fixtures) with a Pydantic mirror (`libs/py-contracts`) and a Zod mirror (`apps/web/src/contracts`). Change the schema, **both** mirrors and the fixtures together. Bump `agent-state.schemaVersion` on breaking changes.
- When `backlog-api` routes or schemas change, regenerate the OpenAPI snapshot (`uv run --package backlog-api python services/backlog-api/scripts/export_openapi.py`) and the web types (`pnpm --filter @backlog/web api:types`). Every database model change needs an Alembic migration (`services/*/migrations`).
- Identity is the normalized **verified email** (no invitations; membership is by email). Every REST route and MCP tool needs an authorization class in `services/backlog-api/tests/test_rbac_matrix.py`. Agent tools reach backlog data only through the MCP server with the user's own token; write tools stay hidden from the model.
- Never log tokens or content; keep secrets out of the repository (dev-only defaults belong in `.env.example` files).
- Keep the UI at WCAG 2.2 AA with 7:1 text contrast (tokens are tested); follow `docs/accessibility.md` and update it when UI behaviour changes.
- `docs/architecture.md` is the architecture/context document for humans and other agents. Read it before larger changes, and update it in the same change whenever structure, configuration, data formats, agent behaviour or features change (or new ones are added).
